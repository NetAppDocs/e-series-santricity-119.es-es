= Conoce la terminología de volúmenes en el software SANtricity
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Aprende cómo se aplican los términos de volumen a tu matriz de almacenamiento.



== Todos los tipos de volumen

[cols="25h,~"]
|===
| Término | Descripción 


 a| 
Capacidad asignada
 a| 
Utilizas la capacidad asignada para crear volúmenes y para operaciones de servicios de copia.

La capacidad asignada y la capacidad informada son las mismas para los volúmenes thick, pero son diferentes para los volúmenes thin. Para un volumen thick, el espacio físicamente asignado es igual al espacio que se informa al host. Para un volumen thin, la capacidad informada es la capacidad que se informa a los hosts, mientras que la capacidad asignada es la cantidad de espacio de la unidad que está asignada actualmente para escribir datos.



 a| 
Aplicación
 a| 
Una aplicación es software como SQL Server o Exchange. Tú defines una o más cargas de trabajo para soportar cada aplicación. Para algunas aplicaciones, el sistema recomienda automáticamente una configuración de volumen que optimiza el almacenamiento. Características como el tipo de E/S, el tamaño del segmento, la propiedad del controlador y la caché de lectura y escritura están incluidas en la configuración del volumen.



 a| 
Capacidad
 a| 
La capacidad es la cantidad de datos que puedes almacenar en un volumen.



 a| 
Propiedad de la controladora
 a| 
La propiedad del controlador define cuál es el controlador designado como propietario o principal del volumen. Un volumen puede tener un controlador preferido (A o B) que "posee" el volumen. La propiedad del volumen se ajusta automáticamente usando la función de equilibrio de carga automático para corregir cualquier problema de equilibrio de carga cuando las cargas de trabajo se mueven entre los controladores. El equilibrio de carga automático proporciona un balanceo automatizado de la carga de trabajo de E/S y asegura que el tráfico de E/S entrante desde los hosts se gestione y equilibre dinámicamente entre ambos controladores.



 a| 
Captura previa de lectura de caché dinámica
 a| 
La precarga dinámica de lectura en caché permite que el controlador copie bloques de datos secuenciales adicionales en la caché mientras está leyendo bloques de datos de una unidad a la caché. Esta caché aumenta la probabilidad de que las futuras solicitudes de datos puedan ser satisfechas desde la caché. La precarga dinámica de lectura en caché es importante para aplicaciones multimedia que usan E/S secuencial. La velocidad y la cantidad de datos que se precargan en la caché se ajustan automáticamente según la velocidad y el tamaño de la solicitud de las lecturas del host. El acceso aleatorio no hace que los datos se precarguen en la caché. Esta función no se aplica cuando la caché de lectura está desactivada.

Para un volumen delgado, la lectura anticipada de caché dinámica siempre está desactivada y no se puede cambiar.



 a| 
Área de capacidad libre
 a| 
Un área de capacidad libre es la capacidad libre que puede resultar de borrar un volumen o de no usar toda la capacidad libre disponible durante la creación del volumen. Cuando creas un volumen en un grupo de volúmenes que tiene una o más áreas de capacidad libre, la capacidad del volumen está limitada al área de capacidad libre más grande en ese grupo de volúmenes. Por ejemplo, si un grupo de volúmenes tiene un total de 15 GiB de capacidad libre y el área de capacidad libre más grande es de 10 GiB, el volumen más grande que puedes crear es de 10 GiB.

Al consolidar la capacidad libre, puedes crear volúmenes adicionales a partir de la cantidad máxima de capacidad libre en un grupo de volúmenes.



 a| 
Host
 a| 
Un host es un servidor que envía E/S a un volumen en una matriz de almacenamiento.



 a| 
Clúster de hosts
 a| 
Un cluster de hosts es un grupo de hosts. Creas un cluster de hosts para que sea fácil asignar los mismos volúmenes a varios hosts.



 a| 
Unidad de repuesto
 a| 
Las unidades de repuesto en caliente solo se admiten con grupos de volúmenes. Una unidad de repuesto en caliente no contiene datos y actúa como reserva en caso de que falle una unidad en volúmenes RAID 1, RAID 3, RAID 5 o RAID 6 contenidos en un grupo de volúmenes. La unidad de repuesto en caliente añade otro nivel de redundancia a tu matriz de almacenamiento.



 a| 
LUN
 a| 
Un número de unidad lógica (LUN) es el número asignado al espacio de direcciones que un host utiliza para acceder a un volumen. El volumen se presenta al host como capacidad en forma de LUN.

Cada host tiene su propio espacio de direcciones LUN. Por lo tanto, el mismo LUN puede ser usado por diferentes hosts para acceder a diferentes volúmenes.



 a| 
Análisis de medios
 a| 
Un análisis de medios permite detectar errores en los medios de las unidades antes de que se encuentren durante una lectura o escritura normal en las unidades. Un análisis de medios se realiza como una operación en segundo plano y analiza todos los datos y la información de redundancia en volúmenes de usuario definidos.



 a| 
Espacio de nombres
 a| 
Un namespace es un almacenamiento NVM formateado para el acceso en bloque. Es análogo a una unidad lógica en SCSI, que se refiere a un volumen en la cabina de almacenamiento.



 a| 
Pool
 a| 
Un pool es un conjunto de unidades agrupadas lógicamente. Puedes usar un pool para crear uno o más volúmenes accesibles a un host. (Creas volúmenes a partir de un pool o de un grupo de volúmenes.)



 a| 
Capacidad de pool o grupo de volúmenes
 a| 
La capacidad de pool, volumen o grupo de volúmenes es la capacidad en una matriz de almacenamiento que se ha asignado a un pool o grupo de volúmenes. Esta capacidad se usa para crear volúmenes y atender las distintas necesidades de capacidad de las operaciones de servicios de copia y objetos de almacenamiento.



 a| 
Caché de lectura
 a| 
La caché de lectura es un búfer que almacena datos que se han leído de las unidades. Los datos para una operación de lectura pueden estar ya en la caché por una operación anterior, lo que elimina la necesidad de acceder a las unidades. Los datos permanecen en la caché de lectura hasta que se vacían.



 a| 
Capacidad notificada
 a| 
La capacidad informada es la capacidad que se informa al host y a la que puede acceder el host.

La capacidad informada y la capacidad asignada son las mismas para volúmenes gruesos, pero son diferentes para volúmenes delgados. Para un volumen grueso, el espacio físicamente asignado es igual al espacio que se informa al host. Para un volumen delgado, la capacidad informada es la capacidad que se informa a los hosts, mientras que la capacidad asignada es la cantidad de espacio de la unidad que está asignada actualmente para escribir datos.



 a| 
Tamaño de los segmentos
 a| 
Un segmento es la cantidad de datos en kilobytes (KiB) que se almacena en una unidad antes de que la matriz de almacenamiento pase a la siguiente unidad de la banda (grupo RAID). El tamaño del segmento es igual o inferior a la capacidad del grupo de volúmenes. El tamaño del segmento es fijo y no se puede cambiar para pools.



 a| 
Segmentación
 a| 
Striping es una forma de almacenar datos en la matriz de almacenamiento. Striping divide el flujo de datos en bloques de un cierto tamaño (llamado "tamaño de bloque") y luego escribe estos bloques en las unidades uno por uno. Esta forma de almacenamiento de datos se usa para distribuir y guardar datos en varias unidades físicas. Striping es sinónimo de RAID 0 y reparte los datos entre todas las unidades de un grupo RAID sin paridad.



 a| 
Volumen
 a| 
Un volumen es un contenedor en el que las aplicaciones, bases de datos y sistemas de archivos almacenan datos. Es el componente lógico creado para que el host acceda al almacenamiento en la storage array.



 a| 
Asignación de volúmenes
 a| 
La asignación de volúmenes es cómo se asignan los LUN de host a un volumen.



 a| 
Nombre de volumen
 a| 
Un nombre de volumen es una cadena de caracteres asignada al volumen cuando se crea. Puedes aceptar el nombre predeterminado o ponerle uno más descriptivo que indique el tipo de datos que se guardan en el volumen.



 a| 
Grupo de volúmenes
 a| 
Un grupo de volúmenes es un contenedor para volúmenes con características compartidas. Un grupo de volúmenes tiene una capacidad y un nivel RAID definidos. Puedes usar un grupo de volúmenes para crear uno o más volúmenes accesibles para un host. (Creas volúmenes a partir de un grupo de volúmenes o de un pool.)



 a| 
Carga de trabajo
 a| 
Una carga de trabajo es un objeto de almacenamiento que admite una aplicación. Puedes definir una o más cargas de trabajo, o instancias, por aplicación. Para algunas aplicaciones, el sistema configura la carga de trabajo para que contenga volúmenes con características de volumen subyacentes similares. Estas características de volumen se optimizan según el tipo de aplicación que admite la carga de trabajo. Por ejemplo, si creas una carga de trabajo que admite una aplicación de Microsoft SQL Server y luego creas volúmenes para esa carga de trabajo, las características de volumen subyacentes se optimizan para admitir Microsoft SQL Server.



 a| 
Caché de escritura
 a| 
La caché de escritura es un búfer que almacena datos del host que aún no se han escrito en las unidades. Los datos permanecen en la caché de escritura hasta que se escriben en las unidades. La caché de escritura puede aumentar el rendimiento de I/O.



 a| 
almacenamiento en caché de escritura con mirroring
 a| 
El almacenamiento en caché de escritura con duplicación se produce cuando los datos escritos en la memoria caché de un controlador también se escriben en la memoria caché del otro controlador. Por lo tanto, si un controlador falla, el otro puede completar todas las operaciones de escritura pendientes. La duplicación de la caché de escritura solo está disponible si el almacenamiento en caché de escritura está activado y hay dos controladores presentes. El almacenamiento en caché de escritura con duplicación es la configuración predeterminada al crear el volumen.



 a| 
Almacenamiento en caché de escritura sin baterías
 a| 
La configuración de almacenamiento en caché de escritura sin baterías permite que el almacenamiento en caché de escritura continúe incluso cuando las baterías faltan, fallan, se descargan por completo o no están completamente cargadas. No se recomienda normalmente elegir el almacenamiento en caché de escritura sin baterías, porque los datos podrían perderse si se pierde la energía. Normalmente, el almacenamiento en caché de escritura se desactiva temporalmente por el controlador hasta que las baterías se cargan o se reemplaza una batería fallida.

|===


== Específico para volúmenes finos

[NOTE]
====
System Manager no proporciona una opción para crear volúmenes delgados. Si quieres crear volúmenes delgados, usa la línea de comandos (CLI).

====
[NOTE]
====
Los volúmenes thin no están disponibles en el sistema de almacenamiento EF600/EF600C o EF300/EF300C.

====
[cols="25h,~"]
|===
| Término | Descripción 


 a| 
Límite de capacidad asignada
 a| 
El límite de capacidad asignada es el tope de cuánto puede crecer la capacidad física asignada para un volumen ligero.



 a| 
Capacidad escrita
 a| 
La capacidad escrita es la cantidad de capacidad que se ha escrito de la capacidad reservada asignada para volúmenes thin.



 a| 
Umbral de advertencia
 a| 
Puedes establecer una alerta de umbral de advertencia que se emitirá cuando la capacidad asignada para un volumen delgado alcance el porcentaje lleno (el umbral de advertencia).
