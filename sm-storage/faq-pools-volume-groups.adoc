= Preguntas frecuentes sobre pools y grupo de volúmenes para SANtricity System Manager
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Esta sección de preguntas frecuentes puede ayudarte si solo buscas una respuesta rápida a una pregunta.



[[what-is-a-volume-group]]
== ¿Qué es un grupo de volúmenes?

Un grupo de volúmenes es un contenedor para volúmenes con características compartidas. Un grupo de volúmenes tiene una capacidad y un nivel RAID definidos. Puedes usar un grupo de volúmenes para crear uno o más volúmenes accesibles para un host. (Creas volúmenes a partir de un grupo de volúmenes o de un pool.)



[[what-is-a-pool]]
== ¿Qué es un pool?

Un pool es un conjunto de unidades agrupadas lógicamente. Puedes usar un pool para crear uno o más volúmenes accesibles a un host. (Creas volúmenes a partir de un pool o de un grupo de volúmenes.)

Los pools pueden eliminar la necesidad de que los administradores supervisen el uso en cada host para determinar cuándo es probable que se queden sin espacio de almacenamiento y evitar las interrupciones convencionales para cambiar el tamaño de los discos. Cuando un pool está a punto de agotarse, se pueden añadir unidades adicionales al pool de forma no disruptiva y el crecimiento de la capacidad es transparente para el host.

Con los pools, los datos se redistribuyen automáticamente para mantener el equilibrio. Al distribuir la información de paridad y la capacidad de reserva por todo el pool, cada unidad del pool puede usarse para reconstruir una unidad con error. Este enfoque no utiliza unidades de reserva en caliente dedicadas; en su lugar, la capacidad de preservación (reserva) se reserva en todo el pool. Cuando ocurre un fallo de unidad, se leen los segmentos de otras unidades para recrear los datos. Luego, se elige una nueva unidad para escribir cada segmento que estaba en una unidad con error, así se mantiene la distribución de datos entre las unidades.



[[what-is-reserved-capacity]]
== ¿Qué es la capacidad reservada?

La capacidad reservada es la capacidad asignada físicamente que almacena datos para objetos de copy service como imágenes de snapshot, volúmenes miembros de consistency group y volúmenes de mirrored pair.

El volumen de capacidad reservada que está asociado a una operación de servicio de copia reside en un pool o un grupo de volúmenes. Tú creas la capacidad reservada a partir de un pool o un grupo de volúmenes.



[[what-is-fdefips-security]]
== ¿Qué es la seguridad FDE/FIPS?

La seguridad FDE/FIPS se refiere a las unidades con capacidad de seguridad que cifran los datos durante las escrituras y descifran los datos durante las lecturas usando una clave de cifrado única. Estas unidades con capacidad de seguridad evitan el acceso no autorizado a los datos de una unidad que se retira físicamente de la storage array.

Las unidades con capacidad de seguridad pueden ser unidades Full Disk Encryption (FDE) o unidades Federal Information Processing Standard (FIPS). Las unidades FIPS se han sometido a pruebas de certificación.

[NOTE]
====
Para volúmenes que requieren soporte FIPS, usa solo unidades FIPS. Mezclar unidades FIPS y FDE en un grupo de volúmenes o pool hará que todas las unidades se traten como unidades FDE. Además, una unidad FDE no se puede añadir ni usar como repuesto en un grupo de volúmenes o pool completamente FIPS.

====


[[what-is-redundancy-check]]
== ¿Qué es la comprobación de redundancia?

Una comprobación de redundancia determina si los datos de un volumen en un pool o grupo de volúmenes son coherentes. Los datos de redundancia se usan para reconstruir rápidamente la información en una unidad de reemplazo si una de las unidades del pool o grupo de volúmenes falla.

Es posible realizar esta comprobación solo en un pool o grupo de volúmenes a la vez. Una comprobación de redundancia de un volumen realiza las acciones siguientes:

* Escanea los bloques de datos de un volumen RAID 3, un volumen RAID 5 o un volumen RAID 6 y luego comprueba la información de redundancia de cada bloque. (RAID 3 solo puede asignarse a grupos de volúmenes usando la interfaz de línea de comandos.)
* Compara los bloques de datos en unidades reflejadas RAID 1.
* Devuelve errores de redundancia si el firmware del controlador determina que los datos son incoherentes.


[NOTE]
====
Si se ejecuta de inmediato una comprobación de redundancia en el mismo pool o grupo de volúmenes, se puede generar un error. Para evitar este problema, se deben esperar uno o dos minutos antes de ejecutar otra comprobación de redundancia en el mismo pool o grupo de volúmenes.

====


[[what-are-the-differences-between-pools-and-volume-groups]]
== ¿Cuáles son las diferencias entre pools y grupos de volúmenes?

Un pool es similar a un grupo de volúmenes, con las siguientes diferencias.

* Los datos en un pool se almacenan aleatoriamente en todas las unidades del pool, a diferencia de los datos en un grupo de volúmenes, que se almacenan en el mismo conjunto de unidades.
* Un pool tiene menos degradación de rendimiento cuando falla una unidad y tarda menos en reconstruirse.
* Un pool tiene capacidad de preservación incorporada; por lo tanto, no requiere unidades de reserva en caliente dedicadas.
* Un pool permite agrupar una gran cantidad de unidades.
* Un pool no necesita un nivel RAID especificado.




[[why-would-i-want-to-manually-configure-a-pool]]
== ¿Por qué querría configurar manualmente un pool?

Los siguientes ejemplos describen por qué querrías configurar manualmente un pool.

* Si tienes varias aplicaciones en tu matriz de almacenamiento y no quieres que compitan por los mismos recursos de unidad, podrías considerar crear manualmente un pool más pequeño para una o más de las aplicaciones.
+
Puede asignar solo uno o dos volúmenes en lugar de asignar la carga de trabajo a un pool más grande que tiene varios volúmenes en los cuales se pueden distribuir los datos. La creación manual de un pool individual dedicado a la carga de trabajo de una aplicación específica puede permitir que las operaciones de cabina de almacenamiento sean más rápidas y con menos contención.

+
Para crear manualmente un pool: selecciona *Almacenamiento* y luego selecciona *Pools & Volume Groups*. Desde la pestaña All Capacity, haz clic en menú:Create[Pool].

* Si hay varios grupos del mismo tipo de unidad, aparece un mensaje que indica que System Manager no puede recomendar automáticamente las unidades para un grupo. Sin embargo, puedes añadir manualmente las unidades a un grupo existente.
+
Para agregar manualmente unidades a un pool existente: en la página Pools & Volume Groups, selecciona el pool y luego haz clic en *Add Capacity*.





[[why-are-capacity-alerts-important]]
== ¿Por qué son importantes las alertas de capacidad?

Las alertas de capacidad indican cuándo añadir unidades a un pool. Un pool necesita suficiente capacidad libre para realizar correctamente las operaciones de la matriz de almacenamiento. Puedes evitar interrupciones en estas operaciones configurando SANtricity System Manager para que envíe alertas cuando la capacidad libre de un pool alcance o supere un porcentaje especificado.

Estableces este porcentaje cuando creas un pool usando la opción *Pool auto-configuration* o la opción *Create pool*. Si eliges la opción automática, la configuración predeterminada determina automáticamente cuándo recibes notificaciones de alertas. Si eliges crear el pool manualmente, puedes determinar la configuración de notificación de alertas; o si prefieres, puedes aceptar la configuración predeterminada. Puedes ajustar esta configuración después en menu:Settings[Alerts].

[NOTE]
====
Cuando la capacidad libre en el pool alcanza el porcentaje especificado, se envía una notificación de alerta usando el método que especificaste en la configuración de alertas.

====


[[why-cant-i-increase-my-preservation-capacity]]
== ¿Por qué no se puede aumentar la capacidad de conservación?

Si se crearon volúmenes en toda la capacidad utilizable disponible, es posible que no se pueda aumentar la capacidad de conservación.

La capacidad de preservación es la cantidad de capacidad (número de unidades) que se reserva en un pool para soportar posibles fallos de unidad. Cuando se crea un pool, el sistema reserva automáticamente una cantidad predeterminada de capacidad de preservación dependiendo del número de unidades en el pool. Si has creado volúmenes en toda la capacidad utilizable disponible, no puedes aumentar la capacidad de preservación sin añadir capacidad al pool, ya sea añadiendo unidades o eliminando volúmenes.

Puedes cambiar la capacidad de conservación desde *Pools & Volume Groups*. Selecciona el pool que quieres editar. Haz clic en *View/Edit Settings* y luego selecciona la pestaña *Settings*.

[NOTE]
====
La capacidad de conservación se especifica como el número de unidades, a pesar de que la capacidad de conservación real se distribuya en las unidades del pool.

====


[[is-there-a-limit-on-the-number-of-drives-i-can-remove-from-a-pool]]
== ¿Hay un límite en la cantidad de unidades que puedo quitar de un pool?

SANtricity System Manager establece límites para la cantidad de unidades que puedes quitar de un pool.

* No se puede reducir la cantidad de unidades en un pool a menos de 11.
* No puedes eliminar unidades si no hay suficiente capacidad libre en el pool para contener los datos de las unidades eliminadas cuando esos datos se redistribuyen a las unidades restantes del pool.
* Puedes quitar un máximo de 60 unidades a la vez. Si seleccionas más de 60 unidades, la opción Quitar unidades se desactiva. Si necesitas quitar más de 60 unidades, repite la operación Quitar unidades.




[[what-media-types-are-supported-for-a-drive]]
== ¿Qué tipos de medios son compatibles con una unidad?

Se admiten los siguientes tipos de medios: Hard Disk Drive (HDD) y Solid State Disk (SSD).



[[why-are-some-drives-not-showing-up]]
== ¿Por qué no aparecen algunas unidades?

En el cuadro de diálogo Add Capacity, no todas las unidades están disponibles para añadir capacidad a un pool o grupo de volúmenes existente.

Las unidades no son elegibles por alguna de las siguientes razones:

* Una unidad debe estar sin asignar y no habilitada para seguridad. Las unidades que ya forman parte de otro pool, otro grupo de volúmenes o están configuradas como hot spare no son elegibles. Si una unidad está sin asignar pero está habilitada para seguridad, tienes que borrarla manualmente para que sea elegible.
* Una unidad que está en un estado no óptimo no es elegible.
* Si la capacidad de una unidad es demasiado pequeña, no es elegible.
* El tipo de soporte de la unidad debe coincidir dentro de un pool o grupo de volúmenes. No puedes mezclar lo siguiente:
+
** Discos duros (HDD) con discos de estado sólido (SSDs)
** NVMe con unidades SAS
** Unidades con tamaños de bloque de volumen de 512 bytes y 4KiB


* Si un pool o grupo de volúmenes contiene todas las unidades con capacidad de seguridad, las unidades sin capacidad de seguridad no aparecen en la lista.
* Si un pool o grupo de volúmenes contiene todas las unidades Federal Information Processing Standards (FIPS), las unidades que no son FIPS no aparecen en la lista.
* Si un pool o grupo de volúmenes contiene todas las unidades compatibles con Data Assurance (DA) y hay al menos un volumen con DA habilitado en el pool o grupo de volúmenes, una unidad que no sea compatible con DA no es elegible, así que no se puede añadir a ese pool o grupo de volúmenes. Sin embargo, si no hay ningún volumen con DA habilitado en el pool o grupo de volúmenes, se puede añadir una unidad que no sea compatible con DA a ese pool o grupo de volúmenes. Si decides mezclar estas unidades, ten en cuenta que no podrás crear ningún volumen con DA habilitado.


[NOTE]
====
Puedes aumentar la capacidad en tu matriz de almacenamiento añadiendo nuevas unidades o eliminando pools o grupos de volúmenes.

====

[[what-is-the-optimal-drive-positioning-for-pools-and-volume-groups]]
== ¿Cuál es la posición óptima de las unidades para pools y grupos de volúmenes?

Al crear pools y grupos de volúmenes, asegúrate de equilibrar la selección de unidades entre las ranuras superior e inferior.

Para las controladoras EF600 y EF300, las ranuras de unidades 0-11 están conectadas a un puente PCI, mientras que las ranuras 12-23 están conectadas a un puente PCI diferente. Para un rendimiento óptimo, debes equilibrar la selección de unidades para incluir un número aproximadamente igual de unidades de las ranuras superior e inferior. Esta colocación garantiza que tus volúmenes no alcancen un límite de ancho de banda antes de lo necesario.



[[what-raid-level-is-best-for-my-application]]
== ¿Cuál es el nivel de RAID óptimo para cada aplicación?

Para maximizar el rendimiento de un grupo de volúmenes, se debe seleccionar el nivel de RAID adecuado. Es posible determinar el nivel de RAID apropiado si se conocen los porcentajes de escritura y lectura de las aplicaciones que acceden al grupo de volúmenes. Utilice la página Rendimiento para obtener estos porcentajes.



[[raid-levels-and-application-performance]]
=== Niveles de RAID y rendimiento de la aplicación

RAID se basa en una serie de configuraciones, llamadas _niveles_, para determinar cómo se escriben y recuperan los datos de usuario y de redundancia de las unidades. Cada nivel de RAID proporciona diferentes características de rendimiento. Las aplicaciones con un alto porcentaje de lectura funcionarán bien usando volúmenes RAID 5 o RAID 6 por el excelente rendimiento de lectura de las configuraciones RAID 5 y RAID 6.

Las aplicaciones con un porcentaje bajo de lectura (de escritura intensiva) no rinden tan bien con volúmenes RAID 5 o RAID 6. El rendimiento degradado resulta de la forma en que una controladora escribe los datos y los datos de redundancia en las unidades de un grupo de volúmenes RAID 5 o RAID 6.

Seleccione un nivel de RAID según la información siguiente.

*RAID 0*

* *Descripción*
+
** No redundante, modo de segmentación.


* *Cómo funciona*
+
** RAID 0 segmenta los datos en todas las unidades del grupo de volúmenes.


* *Funciones de protección de datos*
+
** RAID 0 no se recomienda para necesidades de alta disponibilidad. RAID 0 es más adecuado para datos no cruciales.
** Si falla una sola unidad en el grupo de volúmenes, fallan todos los volúmenes asociados y se pierden todos los datos.


* *Requisitos de número de unidades*
+
** Se requiere un mínimo de una unidad para el nivel de RAID 0.
** Los grupos de volúmenes de RAID 0 pueden tener más de 30 unidades.
** Es posible crear un grupo de volúmenes que incluya todas las unidades en la cabina de almacenamiento.




*RAID 1 o RAID 10*

* *Descripción*
+
** Modo de segmentación/reflejo.


* *Cómo funciona*
+
** RAID 1 utiliza las operaciones de mirroring de discos para escribir datos en dos discos duplicados en simultáneo.
** RAID 10 utiliza la segmentación de unidades para segmentar los datos de un conjunto de parejas de unidades reflejadas.


* *Funciones de protección de datos*
+
** RAID 1 y RAID 10 ofrecen alto rendimiento y la mejor disponibilidad de datos.
** RAID 1 y RAID 10 utilizan las operaciones de mirroring de unidades para realizar una copia exacta de una unidad en otra.
** Si una de las unidades de una pareja de unidades falla, la cabina de almacenamiento puede cambiar instantáneamente a la otra sin perder datos o servicios.
** El fallo de unidad única provoca la degradación de los volúmenes asociados. La unidad reflejo permite acceder a los datos.
** Un fallo de la pareja de unidades en un grupo de volúmenes provoca el fallo de todos los volúmenes asociados, y podría ocurrir una pérdida de datos.


* *Requisitos de número de unidades*
+
** Se requiere un mínimo de dos unidades para RAID 1: una unidad para los datos de usuario y otra para los datos reflejados.
** Si se seleccionan cuatro o más unidades, RAID 10 se configura automáticamente en el grupo de volúmenes: dos unidades para los datos de usuario y dos unidades para los datos reflejados.
** Debes tener un número par de unidades en el grupo de volúmenes. Si no tienes un número par de unidades y te quedan algunas unidades sin asignar, ve a *Pools & Volume Groups* para añadir unidades adicionales al grupo de volúmenes y vuelve a intentar la operación.
** Los grupos de volúmenes de RAID 1 y RAID 10 pueden tener más de 30 unidades. Se puede crear un grupo de volúmenes que incluya todas las unidades de la cabina de almacenamiento.




*RAID 5*

* *Descripción*
+
** Modo de I/O elevado.


* *Cómo funciona*
+
** Los datos de usuario y la información redundante (paridad) se segmentan en las unidades.
** Se utiliza la capacidad equivalente de una unidad para la información redundante.


* *Funciones de protección de datos*
+
** Si una unidad única falla en un grupo de volúmenes RAID 5, todos los volúmenes asociados se degradan. La información redundante permite que aún pueda accederse a los datos.
** Si dos o más unidades fallan en un grupo de volúmenes RAID 5, todos los volúmenes asociados fallarán y se perderán todos los datos.


* *Requisitos de número de unidades*
+
** Se debe contar con un mínimo de tres unidades en el grupo de volúmenes.
** Por lo general, el grupo de volúmenes tiene un límite máximo de 30 unidades.




*RAID 6*

* *Descripción*
+
** Modo de I/O elevado.


* *Cómo funciona*
+
** Los datos de usuario y la información redundante (doble paridad) se segmentan en las unidades.
** Se utiliza la capacidad equivalente de dos unidades para la información redundante.


* *Funciones de protección de datos*
+
** Si una o dos unidades fallan en un grupo de volúmenes RAID 6, todos los volúmenes asociados se degradarán, pero la información redundante permitirá que aún pueda accederse a los datos.
** Si tres o más unidades fallan en un grupo de volúmenes RAID 6, todos los volúmenes asociados fallarán y se perderán todos los datos.


* *Requisitos de número de unidades*
+
** Se debe contar con un mínimo de cinco unidades en el grupo de volúmenes.
** Por lo general, el grupo de volúmenes tiene un límite máximo de 30 unidades.




[NOTE]
====
No puedes cambiar el nivel RAID de un pool. La interfaz de usuario configura automáticamente los pools como RAID 6.

====


[[raid-levels-and-data-protection]]
=== Niveles de RAID y protección de datos

RAID 1, RAID 5 y RAID 6 escriben los datos de redundancia en los medios de la unidad para la tolerancia a fallos. Los datos de redundancia pueden ser una copia de los datos (reflejados) o un código de corrección de error derivado de los datos. Se pueden utilizar los datos de redundancia para reconstruir rápidamente la información en una unidad de reemplazo, en caso de que falle una unidad.

Se configura un nivel de RAID único en un grupo de volúmenes único. Todos los datos de redundancia de ese grupo de volúmenes se almacenan en el grupo de volúmenes. La capacidad del grupo de volúmenes es la capacidad agregada de las unidades miembro menos la capacidad reservada para los datos de redundancia. La cantidad de capacidad necesaria para la redundancia depende del nivel de RAID utilizado.



[[what-is-data-assurance]]
== ¿Qué es la garantía de datos?

La garantía de datos (DA) implementa el estándar de información de protección (PI) T10, con el cual se comprueban y corrigen los errores que se pueden producir durante la transferencia de datos a través de la ruta de I/O con el fin de aumentar la integridad de los datos.

El uso típico de la función Data Assurance comprobará la parte de la ruta de E/S entre los controladores y las unidades. Las capacidades de DA se presentan a nivel de pool y grupo de volúmenes.

Cuando esta función está activada, la matriz de almacenamiento añade códigos de comprobación de errores (también conocidos como comprobaciones de redundancia cíclica o CRC) a cada bloque de datos en el volumen. Después de mover un bloque de datos, la matriz de almacenamiento utiliza estos códigos CRC para determinar si ocurrió algún error durante la transmisión. Los datos potencialmente corruptos no se escriben en el disco ni se devuelven al host. Si quieres usar la función DA, selecciona un pool o grupo de volúmenes que sea compatible con DA cuando crees un nuevo volumen (busca "Yes" junto a "DA" en la tabla de candidatos de pool y grupo de volúmenes).

Asegúrate de asignar estos volúmenes habilitados para DA a un host usando una interfaz de E/S que sea capaz de DA. Las interfaces de E/S que son capaces de DA incluyen Fibre Channel, SAS, iSCSI sobre TCP/IP, NVMe/FC, NVMe/IB, NVME/RoCE e iSER sobre InfiniBand (iSCSI Extensions for RDMA/IB). DA no es compatible con SRP sobre InfiniBand.



[[what-is-secure-capable-drive-security]]
== ¿Qué es secure-capable (Drive Security)?

La seguridad de las unidades es una función que impide el acceso no autorizado a los datos en las unidades habilitadas para seguridad cuando se retiran de la matriz de almacenamiento. Estas unidades pueden ser Full Disk Encryption (FDE) o Federal Information Processing Standard (FIPS).



[[what-do-i-need-to-know-about-increasing-reserved-capacity]]
== ¿Qué debo saber sobre aumentar la capacidad reservada?

Normalmente, deberías aumentar la capacidad cuando recibas un aviso de que la capacidad reservada corre peligro de llenarse. Solo puedes aumentar la capacidad reservada en incrementos de 8 GiB.

* Debes tener suficiente capacidad libre en el pool o grupo de volúmenes para que pueda ampliarse si es necesario.
+
Si no existe capacidad libre en ningún pool o grupo de volúmenes, puedes añadir capacidad no asignada en forma de unidades no utilizadas a un pool o grupo de volúmenes.

* El volumen en el pool o grupo de volúmenes debe tener un estado óptimo y no debe estar en ningún estado de modificación.
* Debe existir capacidad libre en el pool o grupo de volúmenes que quieres usar para aumentar la capacidad.
* No puedes aumentar la capacidad reservada para un volumen snapshot que es de solo lectura. Solo los volúmenes snapshot que son de lectura y escritura requieren capacidad reservada.


Para las operaciones de instantánea, la capacidad reservada suele ser el 40 por ciento del volumen base. Para las operaciones de mirroring asíncrono, la capacidad reservada suele ser el 20 por ciento del volumen base. Usa un porcentaje mayor si crees que el volumen base va a sufrir muchos cambios o si la vida útil estimada de la operación de servicio de copia de un objeto de almacenamiento va a ser muy larga.



[[why-cant-i-choose-another-amount-to-decrease-by]]
== ¿Por qué no puedo elegir otra cantidad para disminuir?

Solo puedes disminuir la capacidad reservada por la cantidad que usaste para aumentarla. La capacidad reservada para los volúmenes miembros solo puede eliminarse en el orden inverso en que se añadieron.

No puedes disminuir la capacidad reservada de un objeto de almacenamiento si se da una de estas condiciones:

* Si el objeto de almacenamiento es un volumen de par reflejado.
* Si el objeto de almacenamiento solo contiene un volumen para capacidad reservada. El objeto de almacenamiento debe contener al menos dos volúmenes para capacidad reservada.
* Si el objeto de almacenamiento es un volumen de snapshot desactivado.
* Si el objeto de almacenamiento contiene una o más imágenes instantáneas asociadas.


Puedes eliminar volúmenes para capacidad reservada solo en el orden inverso en que fueron añadidos.

No puedes disminuir la capacidad reservada para un volumen de instantánea que es de solo lectura porque no tiene ninguna capacidad reservada asociada. Solo los volúmenes de instantánea que son de lectura/escritura requieren capacidad reservada.



[[why-do-i-need-reserved-capacity-for-each-member-volume]]
== ¿Por qué necesito capacidad reservada para cada volumen miembro?

Cada volumen miembro en un grupo de coherencia de instantáneas debe tener su propia capacidad reservada para guardar cualquier modificación hecha por la aplicación host en el volumen base sin afectar la imagen de instantánea del grupo de coherencia referenciado. La capacidad reservada le da a la aplicación host acceso de escritura a una copia de los datos contenidos en el volumen miembro que está designado como lectura-escritura.

Una imagen snapshot de grupo de consistencia no es directamente accesible en lectura o escritura para los hosts. Más bien, la imagen snapshot se utiliza para guardar solo los datos capturados del volumen base.

Durante la creación de un volumen de instantánea de grupo de coherencia que está designado como lectura-escritura, System Manager crea una capacidad reservada para cada volumen miembro en el grupo de coherencia. Esta capacidad reservada le da a la aplicación host acceso de escritura a una copia de los datos contenidos en la imagen de instantánea del grupo de coherencia.



[[how-do-i-view-and-interpret-all-ssd-cache-statistics]]
== ¿Cómo se visualizan y se interpretan todas las estadísticas de caché SSD?

Es posible visualizar estadísticas nominales y detalladas para la caché SSD. Las estadísticas nominales son un subconjunto de las estadísticas detalladas.

Las estadísticas detalladas sólo se pueden ver cuando exportas todas las estadísticas de SSD a un  `.csv` archivo. Al revisar e interpretar las estadísticas, ten en cuenta que algunas interpretaciones se obtienen al observar una combinación de estadísticas.



[[nominal-statistics]]
=== Estadísticas nominales

Para ver las estadísticas de la caché SSD, selecciona menú:Storage[Pools & Volume Groups]. Selecciona la caché SSD que quieres ver las estadísticas y luego selecciona menú:More[View Statistics]. Las estadísticas nominales se muestran en el cuadro de diálogo View SSD Cache Statistics.

En la siguiente lista, se incluyen estadísticas nominales, que son un subconjunto de las estadísticas detalladas.

[cols="25h,~"]
|===
| Estadística nominal | Descripción 


 a| 
en caché/Escrituras
 a| 
La cantidad total de lecturas de host o escrituras de host en los volúmenes con la función de caché SSD habilitada. Compare las lecturas en relación con las escrituras. Las lecturas deben ser mayores que las escrituras para un funcionamiento eficaz de la caché SSD. Cuando mayor sea la proporción de lecturas con respecto a las escrituras, mejor será el funcionamiento de la caché.



 a| 
Aciertos en caché
 a| 
El número de aciertos en caché.



 a| 
Aciertos en caché (%)
 a| 
Se deriva de los aciertos en caché/(lecturas + escrituras). El porcentaje de aciertos en caché debe ser mayor que 50 % para un funcionamiento eficaz de la caché SSD. Una cifra pequeña puede indicar varias cuestiones:

* El ratio de lecturas respecto de escrituras es demasiado pequeño.
* Las lecturas no se repiten.
* La capacidad de la caché es demasiado pequeña.




 a| 
Asignación en caché (%)
 a| 
La cantidad de almacenamiento de la caché SSD que se asigna, expresada como un porcentaje del almacenamiento de la caché SSD que está disponible para esta controladora. Derivado de bytes asignados/bytes disponibles. El porcentaje de asignación de la caché normalmente se muestra como 100 %. Si este número es menor que 100 %, significa que la caché no se preparó o que la capacidad de la caché SSD es mayor que la de todos los datos a los que se intenta acceder. En el último caso, una menor capacidad de caché SSD podría ofrecer el mismo nivel de rendimiento. Es preciso tener en cuenta que esto no indica que los datos en caché se colocaron en la caché SSD; simplemente es un paso de preparación previo a que los datos puedan colocarse en la caché SSD.



 a| 
Uso de caché (%)
 a| 
La cantidad de almacenamiento en la caché SSD que contiene datos de volúmenes habilitados, expresado como un porcentaje del almacenamiento de la caché SSD que se asigna. Este valor representa la utilización o la densidad de la caché SSD derivada de los bytes de datos de usuario/bytes asignados. El porcentaje de utilización de caché generalmente es menor que 100 %, incluso mucho menor. Esta cifra muestra el porcentaje de capacidad de la caché SSD que se llena con datos de caché. Esta cifra es menor que 100 %, ya que cada unidad de asignación de caché SSD, el bloque de caché SSD, se divide en unidades más pequeñas denominadas subbloques, que se llenan de manera bastante independiente. Por lo general, una cifra más alta es mejor, pero las mejoras de rendimiento pueden ser significativas incluso con una cifra menor.

[[what-is-optimization-capacity-for-pools]]
== ¿Cuál es la capacidad de optimización para los pools?

Las unidades SSD tendrán una vida útil más prolongada y un mejor rendimiento de escritura máximo cuando una parte de su capacidad permanece sin asignar.

Para las unidades asociadas a un pool, la capacidad no asignada se compone de la capacidad de preservación del pool, la capacidad libre (capacidad no utilizada por los volúmenes) y una parte de la capacidad utilizable reservada como capacidad de optimización adicional. La capacidad de optimización adicional garantiza un nivel mínimo de capacidad de optimización al reducir la capacidad utilizable y, por lo tanto, no está disponible para la creación de volúmenes.

Cuando se crea un pool, se genera una capacidad de optimización recomendada que proporciona un equilibrio entre el rendimiento, la vida útil de la unidad y la capacidad disponible. El control deslizante de Capacidad de optimización adicional situado en el cuadro de diálogo de Configuración del pool permite ajustar la capacidad de optimización del pool. Ajustar el control deslizante proporciona un mejor rendimiento y vida útil de la unidad a costa de la capacidad disponible, o capacidad disponible adicional a costa del rendimiento y la vida útil de la unidad.

[NOTE]
====
El control deslizante Capacidad de optimización adicional solo está disponible para los sistemas de almacenamiento EF600 y EF300.

====


[[what-is-optimization-capacity-for-volume-groups]]
== ¿Qué es la capacidad de optimización para los grupos de volúmenes?

Las unidades SSD tendrán una vida útil más prolongada y un mejor rendimiento de escritura máximo cuando una parte de su capacidad permanece sin asignar.

Para las unidades asociadas a un grupo de volúmenes, la capacidad no asignada se compone de la capacidad libre de un grupo de volúmenes (capacidad no utilizada por los volúmenes) y una parte de la capacidad utilizable reservada como capacidad de optimización. La capacidad de optimización adicional garantiza un nivel mínimo de capacidad de optimización al reducir la capacidad utilizable y, por lo tanto, no está disponible para la creación de volúmenes.

Cuando se crea un grupo de volúmenes, se genera una capacidad de optimización recomendada que proporciona un equilibrio entre el rendimiento, la vida útil de la unidad y la capacidad disponible. El control deslizante de Capacidad de optimización adicional en el cuadro de diálogo de Configuración del grupo de volúmenes permite ajustar la capacidad de optimización de un grupo de volúmenes. Ajustar el control deslizante permite obtener un mejor rendimiento y vida útil de la unidad a costa de la capacidad disponible, o más capacidad disponible a costa del rendimiento y la vida útil de la unidad.

[NOTE]
====
El control deslizante Capacidad de optimización adicional solo está disponible para los sistemas de almacenamiento EF600 y EF300.

====


[[what-is-resource-provisioning-capable]]
== ¿Qué es capaz de hacer el aprovisionamiento de recursos?

El aprovisionamiento de recursos es una función disponible en las matrices de almacenamiento EF300 y EF600, que permite que los volúmenes se pongan en uso inmediatamente sin ningún proceso de inicialización en segundo plano.

Un volumen con aprovisionamiento de recursos es un volumen grueso en un grupo o pool de volúmenes SSD, donde la capacidad de la unidad se asigna (se asigna al volumen) cuando se crea el volumen, pero los bloques de la unidad se desasignan (no se asignan). En comparación, en un volumen grueso tradicional, todos los bloques de la unidad se asignan durante una operación de inicialización del volumen en segundo plano para inicializar los campos de información de protección de Data Assurance y para que los datos y la paridad RAID sean coherentes en cada RAID stripe. Con un volumen con aprovisionamiento de recursos, no hay inicialización en segundo plano con límite de tiempo. En su lugar, cada RAID stripe se inicializa en la primera escritura en un bloque de volumen de la banda.

Los volúmenes con aprovisionamiento de recursos solo se admiten en grupos y pools de volúmenes SSD, donde todas las unidades del grupo o pool admiten la capacidad de recuperación de errores NVMe Deallocated or Unwritten Logical Block Error Enable (DULBE). Cuando se crea un volumen con aprovisionamiento de recursos, todos los bloques de unidad asignados al volumen se desasignan (sin mapear). Además, los hosts pueden desasignar bloques lógicos en el volumen usando el comando NVMe Dataset Management o el comando SCSI Unmap. Desasignar bloques puede mejorar la vida útil de la SSD y aumentar el rendimiento máximo de escritura. La mejora varía con cada modelo de unidad y capacidad.


NOTE: DULBE no es compatible con las matrices de almacenamiento EF300C o EF600C en este momento.
