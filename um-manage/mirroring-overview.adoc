= Conoce la duplicación de SANtricity
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
SANtricity Unified Manager incluye opciones de configuración para las funciones de mirroring de SANtricity, que permiten a los administradores replicar datos entre dos arrays de almacenamiento para la protección de datos.

[NOTE]
====
La duplicación síncrona no está disponible en el sistema de almacenamiento EF600/EF600C o EF300/EF300C.

====


[[types-of-mirroring]]
== Tipos de mirroring

Las aplicaciones SANtricity incluyen dos tipos de mirroring: asíncrono y síncrono.

La réplica asíncrona copia volúmenes de datos bajo demanda o según un calendario, lo que minimiza o evita el tiempo de inactividad que podría resultar de la corrupción o pérdida de datos. La réplica asíncrona captura el estado del volumen primario en un momento concreto y copia solo los datos que han cambiado desde la última captura de imagen. El sitio primario puede actualizarse inmediatamente y el sitio secundario puede actualizarse a medida que lo permita el ancho de banda. La información se almacena en caché y se envía más tarde, a medida que los recursos de red estén disponibles. Este tipo de mirroring es ideal para procesos periódicos como backup y archivado.

La replicación síncrona replica los volúmenes de datos en tiempo real para garantizar disponibilidad continua. El propósito es lograr un objetivo de punto de recuperación (RPO) de cero datos perdidos al tener una copia de los datos importantes disponible si ocurre un desastre en una de las dos storage arrays. La copia es idéntica a los datos de producción en todo momento porque cada vez que se realiza una escritura en el volumen primario, se realiza una escritura en el volumen secundario. El host no recibe un acuse de recibo de que la escritura fue exitosa hasta que el volumen secundario se actualiza con los cambios que se hicieron en el volumen primario. Este tipo de replicación es ideal para fines de continuidad de negocio como la recuperación ante desastres.



[[differences-between-mirroring-types]]
== Diferencias entre los tipos de mirroring

La siguiente tabla describe las principales diferencias entre los dos tipos de mirroring.

[cols="1a,1a,1a"]
|===
| Atributo | Asíncrono | Sincrónico 


 a| 
Método de replicación
 a| 
Punto en el tiempo -- La réplica se realiza bajo demanda o automáticamente según un calendario definido por el usuario.
 a| 
Continuo -- El mirroring se ejecuta automáticamente de forma continua, copiando datos de cada escritura del host.



 a| 
Distancia
 a| 
Admite largas distancias entre matrices. Normalmente, la distancia está limitada solo por las capacidades de la red y la tecnología de extensión de canales.
 a| 
Restringido a distancias más cortas entre matrices. Normalmente, la distancia debe estar dentro de unos 10 km (6.2 millas) de la matriz de almacenamiento local para cumplir los requisitos de latencia y rendimiento de la aplicación.



 a| 
Método de comunicación
 a| 
Una red IP o Fibre Channel estándar.
 a| 
Solo red Fibre Channel.



 a| 
Tipos de volumen
 a| 
Estándar o thin.
 a| 
Solo estándar.

|===
